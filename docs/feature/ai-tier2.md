# AI 能力档位与第二档「实战档」开发计划

> 状态：M1 已实施（W0 + W6 + 公平性护栏 + 档位分发器，2026-11-15）· 首份基准见 `ai-tier2-baseline.md`
> 负责人：待定 · 目标读者：本项目维护者。前置阅读：`src/domain/ai/` 现有实现、`docs/feature/`（本目录）。

## 1. 背景与目标

当前 AI 是一套**确定性加权启发式**（`decider.ts` + `efficiency.ts` + `defense.ts`），与人类共用
`PlayerView` 这一唯一信息入口，信息对称性在架构上是成立的。但它对同样的可见信息加工得很浅：
一步贪心、静态危险表、无攻守切换、无读牌。因此在「老手」档对抗真实人类时强度不足。

**目标**：在不引入神经网络、不破坏信息对称、不放弃可解释性的前提下，新增一档更强的 AI
（第二档「实战档」），使 AI 陪练在与人类玩家对局时具备实质威胁；档位可在设置中配置，
第一档保持现有行为不变。

**设计红线**（任何改动不得违反）：

1. AI 只能通过 `PlayerView` 获取信息——禁止接触 `GameState` 暗牌、禁止读取 RNG 种子；
2. 决策必须可解释——每个动作仍输出结构化 `DecisionReason`；
3. 第一档（现有行为）零回归——现有测试全部保持通过。

## 3. 公平性护栏（新增测试）

1. **属性测试**（已落地 `tests/domain/ai/fairness.test.ts`）：构造「相同 `PlayerView`、不同暗牌」
   的两组 `GameState`——克隆同一状态、对换牌墙中两张未揭示且不同的牌（墙内容不在任何视图里），
   断言各档决策器输出的动作完全一致。多 seed × 多步推进覆盖行动与宣称阶段；
   二档落地后在测试内 `DECIDERS` 表追加一行即获得同等约束，rollout 若偷读墙序会在此失败。
2. **接口约束**：第二档所有新模块（rollout、读牌）只 import `PlayerView` 与 tile/rule 纯函数，
   code review 时按此检查；不新增任何从 `GameState` 直读的字段。
3. RNG 说明：模拟测试用固定 seed 造局是允许的（造局 ≠ 决策输入）；决策器内部如需随机
   （见 8.2 开放问题），必须用与牌局无关的独立随机源（如以视图哈希为种子的内部 PRNG），
   且结果仍须可复现。

## 4. 第二档技术方案

按实施顺序分六个工作流。W0/W6 是地基，先行。

### W0 缺口修复（一档内即生效，独立小改）✅ 已实施（2026-11-15）

- **暗杠/补杠永不执行**：`GameAction` 有 `anGang`/`buGang`（`legalActions` 一直在生成，
  engine.ts:72,77），但 `decideDiscard` 只考虑胡/打。已补上，策略为：
  - 前置：`wallCount ≥ 1`（否则杠后 `drawTo` 立即流局）；
  - 杠后向听 ≤ 最优打牌向听（保持/改善）才执行，暗杠优先于补杠（隐蔽性更高）；
  - 杠后听牌时要求等待仍有剩余张（`listWaits` 天然跳过已见满 4 张的牌）——避免听在自家死张上；
  - 补杠升级已有碰、副露数不变（引擎 `applyAction` 语义），杠不改变已见牌计数。
  - 实测发现：标准形下暗杠几乎从不恶化向听（副露替代手内刻子 + 去浮牌），
    唯一常见恶化场景是七对子/国士形（副露数 > 0 直接失形），向听比较天然覆盖。
- **现物按座位区分**：`defense.ts` 原把「任一对手弃牌里出现」一律按安全处理。
  ⚠️ 实施时确认：**本引擎没有振听/过水规则**（全 src 无此语义，claims 只在弃牌后触发一次），
  「现物永久安全」不成立，故实现为证据折算而非归零：
  - 弃出过该牌的对手 ×0.25（最强证据：亲自弃出）；其余对手 ×0.6（弱证据：该牌弃出时
    无人宣称）；全新生张无证据，保持基础危险度；
  - 标量 = 三家危险度的均值（W2 升级为逐家向量时此实现已是向量内积形式）。
- **补杠风险评估**：本引擎 claims 只由弃牌触发，无抢杠宣称窗口（`yaku.ts` 定义了 `qianggang`
  番种但流程未接）——补杠在当前引擎内零被抢风险；未来实现抢杠时需重评补杠默认策略。
- 验收：现有单测全过（新增暗杠/补杠/现物折算 8 用例）；千局模拟通过且胡牌率不降（数据见
  `ai-tier2-baseline.md`）；重跑 `scripts/calibrate.ts` 确认教练阈值（W0 移动一档决策分布）。

### W6 强度基准与调参闭环（一切优化的度量前提）

- 新脚本 `scripts/tournament.ts`：固定 seed 集，两个决策器配置对打（交替座位抵消先手），
  输出胡牌率 / 平均番数 / 点炮次数 / 平均得分差。支持 `--tier1 --tier2 --games N`。
- 输出对比报告存 `docs/feature/ai-tier2-baseline.md`（首次基准结果）。
- 此后每个工作流合入前跑一次对打，用数据说话。
- 验收：能稳定复现「改动前后」差异；首份基准报告落档。

### W1 期望得分评估（进张数 → 期望分）

- 现状：`scoreOf` 只比「向听 + 进张张数」，不区分好形/愚形、不区分能胡多大。
- 做法：对**向听 ≤ 1** 的候选打出，枚举其成胡等待张（引擎已有 `listWaits`，
  engine.ts:24，直接复用），调用现有 `yaku.ts` / `score.ts` 精确算番，
  按「剩余张数 × 该等待的分值」求和，得到候选的期望得分。向听 ≥ 2 的候选
  **没有可枚举的成胡等待**，沿用现有 ukeire 评分（退化路径，也是性能护栏——
  十向听手牌全候选跑 canWin 枚举不可行）。
- **档位门控（红线 3）**：期望分作为独立评分项，仅在 aiTier=2 时参与加权；
  一档 `scoreOf` 行为保持不变，教练在一档下的对比基线不受影响。
  （一档 `FAN_WEIGHT=4` 形同虚设的问题由本项在二档语境下解决；若要单独修一档，
  属于独立小改并需重跑 calibrate，不在 W1 范围内。）
- 收益：好形愚形、字牌刻子价值、清一色方向价值自动显现。
- 改动点：`efficiency.ts`（新增 expectedScore 计算，仅对向听 ≤1 候选，复用向听缓存模式）、
  二档评分函数。
- 验收：构造已知好形/愚形手牌的单元测试；千局模拟耗时仍在预算内。

### W2 读牌推理层（危险度从静态表升级为逐张 × 逐家估计）

- 特征全部来自已有 `PlayerView`，无新信息需求：
  - **筋**：对手打过 5m → 其 2m/8m 危险度下调（三种规则集均支持吃，筋逻辑通用）；
  - **副露**：碰 5m → 对该家 4m/6m 提危；吃 4-6 → 对该家 5 提危；
  - **壁**：某张已见 3 张 → 含它的坎张/边张听牌概率下调；
  - **巡目与进度**：用 `discards[seat].length + melds` 推断该家巡目，`wallCount` 残局放大危险度。
- 实现：`defense.ts` 内新增特征打分函数，输出「对每家」的危险度向量。
  W0 已把标量实现改为「逐家计算后取均值」的内积形式（见 W0），W2 只需把
  均值聚合替换为按档位加权/取 max，一档继续用均值。
- 验收：已知局面（对手碰中张后）危险度排序正确的单元测试。

### W3 攻守切换（push/fold）

- 现状：防守只是线性减分（`DANGER_WEIGHT=0.8`），永远不弃攻。
- 做法：W1 的成胡期望 ×（自身胡率估计）对 W2 的点炮概率 × 典型放炮分值，
  期望为负且自身向听 ≥ 2 时切换守势模式——按安全度排序出牌（现物 → 字牌已见 3 → 壁张）。
- 改动点：`decider.ts` 新增模式分支；`wallCount` 首次进入决策。
- 验收：构造「远离听牌 + 对手明显听牌」局面，断言切守势；对打基准点炮次数显著下降。

### W4 Monte Carlo rollout 出牌搜索（第二档主力武器）

- 做法：对确定性评分 top-k 候选（k ≤ 5），从未见牌墙均匀采样发对手暗牌与后续摸牌，
  用轻量策略（纯效率、复用向听缓存）模拟到终局或深度上限，
  统计各候选的胡率 / 期望分 / 点炮率，取综合最优。
- **分层纪律**：决策核心保持**同步纯函数**（模拟测试与 tournament 才能直接复用），
  Web Worker 只是 UI 侧的异步包装——Play 页的 `setTimeout` 同步 step 流需要加一层
  async 桥接（M4 的工作量里要计入）。禁止把 rollout 本身写成异步。
- 公平性：从未见牌池采样 = 人类脑内的剩牌概率推理，不含任何暗牌信息（红线 1 仍由属性测试保障；
  墙序属于暗牌，rollout 读墙序会在 fairness 测试中失败）。
- 性能：迁入 Web Worker（`src/domain/ai/` 纯 TS、无 DOM 依赖，迁移成本低）。
  参数**保守起步**：top-k ≤ 5、rollouts 32~64、深度 6 巡，M4 以实测校准后再放宽
  （全量 top5 × 128 rollouts × 8 巡 ≈ 7 万+ 次向听调用，300ms 均值预算下不保守）。
  另注意向听缓存 key 为 `counts.join(',')` 字符串拼接，rollout 高频下字符串成本
  可能占比显著，M4 先实测再决定是否换数值 key。
- 可解释性：决策理由仍由确定性层生成（效率/危险/期望分），新增一条
  「模拟 N 局：此打法胡率 x%、放炮率 y%」的 rollout 统计理由，保持人话输出。
- 验收：千局模拟（本地）无异常；决策耗时满足 6 节预算；对打基准相对一档显著占优。

### W5 鸣牌 EV 决策

- 碰/吃后重算 W1 期望分，与门清慢速路线比较再决定；评估愚形碰与番种破坏。
- 明杠从「恒杠」改为评估：门清损失 + 杠后打牌危险度。
- 验收：构造碰后愚形 / 破坏清一色的已知局面，断言选择正确；对打基准无回归。

## 6. 性能预算

- 一档：维持现状（SC-3：均值 < 50ms，p99 < 500ms），CI 不变。
- 二档：Worker 内执行，目标**均值 ≤ 300ms、p99 ≤ 1s**（人类对局中属自然思考节奏；
  精确数值在 M4 以实测校准）。CI 只跑一档千局与守恒断言；二档千局（本地）沿用
  `vitest.sim.config.ts` 模式，仅本地/真机验证耗时。

## 8. 风险与开放问题

### 8.1 风险

- **性能超预算**：rollout 成本失控。缓解：先 W1/W2/W3（全确定性）落地，W4 参数保守起步
  （见 W4 修订），实测校准；缓存体系（`efficiency.ts` 向听缓存、等价类去重）全部复用。
- **可解释性稀释**：rollout 主导决策后理由可能与选择脱节。缓解：rollout 只在确定性层
  top-k 内选择，理由仍出自确定性层并附模拟统计。
- **教练阈值漂移**：`COACH_THRESHOLDS` 由一档分布校准。W0 已移动一档决策分布
  （暗杠 + 现物折算），M1 已重跑 `calibrate.ts` 确认（结果见基准报告）；二档落地后
  每档需各自校准。

### 8.2 拍板记录（2026-11-15）

1. 档位命名采用「经典 / 实战」（UI 文案，M6 接线时生效）。
2. ε 随机 tie-break：**采纳前提下的实现方式定为**以视图哈希为种子的内部 PRNG——
   与牌局 RNG 无关、同视图可复现（满足护栏第 3 条），是否启用在 M5 调参后以基准数据决定。
3. 二档先只出「实战」单档；6 组合（难度 × 档位）的权重再标定等 M5 调参完成后再拆。
4. 教练按与对局一致的档位评估（同档对比才有教学意义）；二档阈值需单独校准（见 8.1）。

## 9. 不做什么

- 不引入神经网络 / 预训练模型 / 运行时推理依赖；
- 不改动规则引擎、番种计算、题库（W1 仅调用 `score.ts`，不修改其行为）;
- 不在第一阶段追求逐巡完美博弈——目标是「对人类有实质压力」，不是 Suphx 级强度。
